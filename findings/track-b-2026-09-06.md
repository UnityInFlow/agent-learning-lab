2. **What the scare uncovered is real and is still unfixed.** `runner/run-agent.sh:1177` builds
   the run record in memory, POSTs it, and **archives no copy**. Nothing backs the volume up.
   Had the database actually been wiped, roughly 250 run records across stops 4–11 would have
   been unrecoverable, and reconstructing one from a committed table would fabricate a record
   claiming a completeness it does not have. `HANDOFF.md` item **00b**.
3. **Every colima host port-forward on this machine is dead in a way that reads as healthy.**
   `nc -z 127.0.0.1 8081` reports **OPEN**; `curl` returns **000**. A half-open forward is worse
   than a closed port because a port check calls it healthy. The route, not a repair: SSH tunnels
   into the VM (`18081`→8081 API, `14318`→4318 OTLP-HTTP, **`14317`→4317 OTLP-gRPC**, `15174`,
   `13001`, `19090`, `13200`). **The gRPC one is the one that matters for a claude run** —
   `runner/lib/telemetry-env.sh:53` sets `OTEL_EXPORTER_OTLP_PROTOCOL=grpc`, so overriding the
   HTTP port alone **silently drops every event**, which is exactly what happened to stop 11's
   deliberate-failure batch. Any future batch passes `OTLP_GRPC_PORT=14317` and checks that
   `events.jsonl` grows before trusting a telemetry-sourced outcome.
