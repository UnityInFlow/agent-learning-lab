## The finding of the stop is about the instrument, and it is mine

`GUARDRAILS.md`'s layer rule was **misapplied in six places** and the stop's own §4a review caught
it. The `sha256` archive-digest refusal and the `claude-community` commit-SHA pin were labelled
**L1** in four places in `phases/07-plugins/README.md` and two in `SOURCES.md` — one of them the
Claude Code sandbox row, reading *"a real Layer 1 boundary"*.

Applied in order, stopping at the first yes: **can the bad value still be written down after the
fix?** It **can** — a marketplace entry may still name a wrong digest, and the archive at the URL
may still be swapped. So step 1 is `no`, and the rule falls through to step 2, *does something
execute and reject it*, which is exactly what compare-then-refuse is. **They are L2.**

The correction **sharpens** the claim rather than softening it: a lockfile is L1 *because* the bad
value cannot be written, so calling these refusals lockfile-shaped was the error and not just the
label. The workspace `CLAUDE.md` warns about the opposite direction of this mistake — *"a schema
note is L3, not L1"* — and records that mistaking one for a control **already cost a voided
twenty-run experiment**. This is the same error pointing the other way, in the phase whose whole
job was to apply the rule to seven Bank controls.

**One finding was answered by observation instead of argument, and the observation went against the

with the command in the cell.

**A claim about a control's failure direction was backwards.** *"A deny-list that normalizes and an

Chasing a review finding about arithmetic exposed a defect in a registered instrument nobody was
auditing. `SOURCES.md`'s header claimed *"the same 76 URLs"* while `ok=64 moved=8 blocked=2` = **74**.

`check-links.sh` in fact reports *"Checking 91 unique URLs"* across **34 files**, not just
`SOURCES.md`, and the 2026-09-27 run's `71+11+2` = **84** — **seven URLs in no bucket**. The same
gap stood at **two** on 2026-08-28, so it is not new: **it grew with the corpus, and no run of this
checker has ever reconciled.** The checker prints only its non-`ok` lines (13 on 2026-09-27,
re-derived with `grep -cE '^(✅|↪️|🔒|🔑|⚠️|❌)'`), so the missing seven **cannot be recovered from
the output at all**.

**What this does not invalidate:** `broken=0` is the clause the CI job *verified reading is still
verified* gates on, and it is unaffected — a broken URL is printed, and none was. **What it does
invalidate** is any sentence of the form *"all N sources verify"*, because **N is not knowable from
this output**. No stop's gate relies on such a sentence. The summary fix is an L2 instrument change
and §6 forbids a future step's artifact at a ◇ stop, so it is on record for the author.
