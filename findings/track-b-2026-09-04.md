## Stop 8 in more detail, because two of its findings are about the instrument

**The halt that opened it was on the wrong premise.** It claimed a Claude Code project skill
*cannot be delivered to a BE-003 run*, blaming the path. The cause was
`--disable-slash-commands` — *"Disable all skills"* — passed by the runner on every claude run
this project has ever done. **6 of 6 activated without it, 0 of 6 with it, at both paths,
p = 0.0022.** The halt's own probe was hand-run with the runner's flags **minus that one**.

**Four instrument defects, one shape, seen from both sides.** Three rounds of *everything not
`bundled` is MINE* in `tools/skill-activation.sh` — each of which would have credited a foreign
activation to the treatment **on the control arm** — and one *every skill is THEIRS* in the
runner's contamination guard, which marked the first matched-arm run `F15 — EXCLUDE from
comparisons` for loading the skill it was given. Every matched run loads a skill, so that guard
would have ended the batch with **arm B at `n = 0`**.

**What the instrument can now say:** `skill.source` for a project-scope skill is
`projectSettings`, the first ever recorded here. **What it still cannot:** tell two installed
skills apart — `skill.name` is redacted to `custom_skill`.

## The one finding most likely to overturn the track's result

**Stop 8's control is clean for activation and is not clean for behaviour, and this is the only
row in the table above that could move.**

Three of the four rubric categories are constant across all fifteen runs. The entire spread sits
in `maintainability`, whose anchor 2 is word-for-word the first bullet of the skill body. On it,
the **misdescribed arm scores like the matched arm** (4 of 5 vs 5 of 5, p = 1.0) and **unlike the
control** (1 of 5; pooled treated vs control, p = 0.017) — **while never having activated the
skill.**

It is not a result and is not recorded as one: `maintainability` was never a registered outcome,
so it sits on the same shelf as B3's test-writing asymmetry. But two mechanisms produce it and
this design cannot separate them:

1. **The file was read, not selected.** Arm C's `SKILL.md` is a tracked file in the worktree.
   **Measured as possible, not speculated:** 1 of 6 runs with skills *disabled* emitted the skill
   body's marker after reading `SKILL.md` as an ordinary file, which is why this experiment's
   detector is a `Skill` tool_use and not a text marker.
2. The arms differ by more than the skill — arm A has no `.claude/` directory at all.

**If (1) is what is happening, then the activation result stands and every behavioural reading of
a skill on this instrument is confounded** — including anything B6 would later claim about a
specialist skill. It cannot be settled from disk: `tool_result` telemetry carries `tool_name` and
no file path, and the kept agent logs hold only the final message. **A fourth arm settles it in
five runs**, and §7 reserves a new arm for the author.
